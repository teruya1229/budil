# Budil×GPT 端末内・作業完了→請求→入金の現行仕様

## 1. 作業完了と請求書作成（段階別）

1. 「田中さんの作業を完了にして請求書を作って」→端末読取に同意→対象の作業を1件選択。
2. 実作業日・実金額・税込/税抜を入力。プレビューで照合した後に**作業完了＋売上登録を承認**。ここでは請求書はまだ作らない。
3. 同じ作業について請求日・支払期限・入金予定日・振込方法を指定→請求書プレビュー→**別の承認**で未入金の請求下書きを端末に保存。
4. 下書き保存後、金額・宛名・日付を再確認し、未送信である旨のチェックを付けて**請求確定**。請求書の `status` が `draft` → `issued` になる。
5. 帳票管理でPDFを確認し、顧客への送信・手渡しは本人が実施する。**請求確定ボタンは外部送信や入金済みへの変更を行わない。**

作業完了・売上・帳票は別々の保存キーなので、完全な一括トランザクションではない。作業完了後の請求作成に失敗しても、**再読込後に同じ対象作業を選び、未完了の請求段階から再開**できる。途中成功を全工程完了と表示しない。

## 2. 承認済み見積→請求書

「その見積を請求書にして」は、現セッションの承認済み見積のみ対象。金額・税・明細は原文書を保持し、見積書と請求下書きを同一の帳票コレクションへ保存する。請求確定は別のチェック・確定操作を必要とする。元見積は書き換えない。

再読込後でも「請求書の下書きを確定して」（または「保存済み請求書を確定して」）→端末読取同意→対象の保存済み請求書を1件選択→内容確認・明示承認で `issued` に進められる。21件以上の候補は自動選択しない。

## 3. データ保護と誤操作防止

- 保存・請求確定ごとにバックアップを取得し、読戻しで検証。保存が失敗した場合は旧状態に戻す。ロールバック失敗は明示。
- 同一請求番号、同じ作業への二重請求、請求確定の二度押し、元データ更新・財務状態不整合を拒否。
- 金額・税区分・日付を勝手に推測しない。端末内の保存だけで、メール送信・Googleカレンダー書込・銀行API・自動入金確定なし。
- `issued` は**端末内で請求確定した状態**を表し、顧客がPDFを受け取った証拠ではない。

## 4. 銀行CSV照合との関係

銀行CSV照合は、請求済み（`issued`）かつ銀行振込・未入金・全額一致・独立した入金明細IDを持つ請求書だけを候補にする。

**作業売上と紐づく請求書は、別の売上レコードとの不整合を防ぐためCSVでの自動入金更新を拒否**する。そのケースでは通常のBudil管理画面で売上・請求双方の入金状態を確認し、本人が処理する。
