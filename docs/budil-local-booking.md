# Budil 予約機能：端末内予定＋既存Googleカレンダー読取

## 会話による操作

- `金曜日の午前10時、空いてる？`：本人の端末内作業予定を確認。必要に応じて**Googleカレンダーの読取同意チェック→確認ボタン**で、既存Supabase `make-proxy` の `schedule_blocks_list` を呼ぶ。接続済みカレンダーの時刻の重複件数のみ表示し、タイトル・場所・顧客情報は表示しない。
- `金曜日の10時に田中さんのエアコン洗浄2台を予約して。18,000円で見積書も作って`：税込/税抜、終了時刻、顧客候補を本人が指定。重複を確認した後に、予約・見積の下書きを表示。本人操作で端末内作業予定だけを `tentative` で保存する。
- `田中さんの予約を土曜日に変更して`：対象作業を1件選び、変更先の重複を確認してから、端末内予定だけを更新する。

## Googleカレンダーの安全境界

- 読取は**明示的な毎回のチェックとクリック**のときだけ行う。ログイン済みユーザーのJWTが必要。
- クライアントの送信内容は `{operation:'schedule_blocks_list',startDate,endDate}` のみ。顧客名・住所・見積内容・カレンダーID・テナントIDは送らない。
- サーバーは既存の有効なtenant bindingから対象カレンダー・認証・タイムゾーンを選ぶ。ユーザーが任意のカレンダーへ照会先を切り替えることはできない。
- 返却イベントの `summary`、`location`、`id` はブラウザのクラウドクライアントで破棄して `start/end` だけにする。日時不正・通信不明の場合は**空き不明**として扱う。
- 読取結果で重複が見つかった場合、同じ未保存予約の保存は停止。再確認できるまで勝手に登録しない。
- 何も見つからない場合も「照会したカレンダーで照会時点の重なりなし」であり、すべてのカレンダーの空き確定ではない。
- **Googleカレンダーへの予約登録・変更・削除は未実装/未許可**。保存先は端末内の作業予定だけで、Googleへの自動同期は行わない。

## 保護・検証

- 端末内保存の直前に安全バックアップ、日時重複・変更差分の再検査。
- 終日・日付不明・複数日・時刻不明の既存予定は自動で「空き」と判断しない。
- 検証：`scripts/verify-budil-gpt-booking.mjs`、`scripts/verify-budil-gpt-public-read.mjs`、`scripts/verify-budil-gpt-booking-browser.mjs`。
- 統合開発ブランチのみで、実JWT・本番カレンダーへの読取およびiPhone/Android実機の最終受入は未確認。
