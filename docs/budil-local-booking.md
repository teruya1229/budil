# 端末内予約の確認手順

AI業務番頭を開き、端末データ読取にチェックしてから指示を実行する。

- `金曜日の午前10時、空いてる？`：端末内の有効な作業予定を照合する。Google Calendarの空き確定ではない。
- `金曜日の10時に田中さんのエアコン洗浄2台を予約して。18,000円で見積書も作って`：税込・税抜、終了時刻、顧客候補を本人が指定する。重複を確認した後、予約と見積の未保存下書きを表示する。見積PDFは従来の承認操作後に出力できる。予約保存ボタンは端末内作業予定だけを `tentative` で保存する。
- `田中さんの予約を土曜日に変更して`：候補の作業予定を1件選び、変更先と重複を確認する。保存ボタンで端末内のその1件だけを変更する。

予約保存・変更の直前に、作業予定全体の安全バックアップを作る。保存時に対象と競合を再確認し、変化があれば停止する。Google Calendarは変更しない。時刻不明、終日、複数日、カレンダー取り込み候補の変更は対象外。

検証：`node scripts/verify-budil-gpt-booking.mjs`、`node scripts/verify-budil-gpt-booking-browser.mjs`（使い捨て Chrome、架空データ、390px）、`node scripts/audit-budil-original-19.mjs`。19件監査は実画面 fixture で検証した経路だけを `E2E_VERIFIED` とする。
