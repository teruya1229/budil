# Local bank CSV reconciliation

Say `銀行明細と請求書を照合して`, consent to reading local invoices, then select a CSV in the Budil×GPT panel. Enter a stable bank/account label and choose UTF-8 or Shift_JIS. The file is decoded in the browser with fatal decoding, is limited to 2 MB, and its raw contents are not persisted or transmitted. The account label is used with the transaction ID for duplicate detection; use the same label on every import of that account.

The first row must be headers. Supported date headers: `日付`, `取引日`, `お取引日`, `入出金日`, `年月日`. Description: `摘要`, `取引内容`, `お取引内容`, `依頼人名`, `振込依頼人`. Amounts: a dedicated `入金`, `入金額`, `お預入れ`, `預入金額`, or `貸方金額` column, optionally with `出金`, `出金額`, `お引出し`, `払出金額`, or `借方金額`; or `入出金区分`/`取引区分`/`区分` plus `金額`/`取引金額`. The explicit direction must be `入金`, `預入`, `credit`, or `deposit`. A populated debit column rejects the row. For payment updates, `取引ID`, `取引番号`, `明細番号`, or `取引識別番号` is required. CSV quoting, escaped quotes, and quoted newlines are supported. Dates accept `YYYY-MM-DD`, `YYYY/MM/DD`, and `YYYY年M月D日`. Amounts are positive whole yen, optionally grouped with commas inside quoted cells.

Only `issued` bank transfer invoices with an explicit PaymentBrain `pending`/`未入金` status, no paid amount, exact total yen, and a deposit dated from issue date through 90 days after due date are candidates. The description must contain the invoice number or full customer name. The panel shows every candidate, evidence, confidence, and excluded line. More than one candidate cannot be applied. One explicit checkbox and one exact invoice/deposit button are required; this changes no payment automatically. The update takes a Budil safety backup, applies `PaymentBrain.buildPaidPatch`, writes the local documents collection, and reads it back. Reimporting an assigned transaction ID blocks another payment.

Rows without a stable transaction ID can be previewed but require manual payment confirmation in Budil's normal records. A linked revenue record is blocked from this CSV write because documents and revenue are separate localStorage collections and cannot be changed atomically. Unissued, partially paid, cancelled, ambiguous, out-of-window, and amount-mismatched invoices are excluded. The CSV flow does not connect to a bank, verify that a bank transaction is authentic, write Google data, or support split payments.
